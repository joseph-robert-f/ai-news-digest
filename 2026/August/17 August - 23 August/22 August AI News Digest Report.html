It's part of a broader pattern of similar Nvidia licensing-plus-hiring deals with AI startups this year.

A critical MLflow flaw is under active exploitation, letting attackers lift cloud credentials from exposed servers

Why it matters: MLflow tracking servers sit at the center of ML pipelines with direct access to cloud IAM roles and secrets, and this flaw needs no authentication — if your team stood one up without locking it behind a network boundary, it may already have been scanned and hit.

Detail & sources

CVE-2026-64849, an unauthenticated server-side request forgery flaw affecting all MLflow versions before 3.15.0, was disclosed August 18; watchTowr's honeypot network detected exploitation attempts within hours. The default MLflow Tracking Server exposes its model-registry webhooks API without authentication, and one endpoint returns the full upstream response to the caller — letting an attacker reach internal cloud metadata services and pull AWS IAM tokens, GCP service-account keys or Azure Managed Identity credentials. An SSRF protection added in version 3.10.0 can be bypassed. CISA has warned federal agencies and organizations running exposed MLflow instances to patch immediately, audit logs for prior compromise, and rotate any credentials that may have been reachable.

Developer Platforms19 Aug

GitHub's postmortem on its Aug 17 outage: a monitoring gap plus a VS Code retry bug turned a capacity blip into 8 hours down

Why it matters: The root cause wasn't a single dramatic failure but a misconfigured alert that missed a sidecar's concurrency limit, then a latent client-side bug that turned millions of laptops into an accidental traffic amplifier — a reminder that retry logic without limits is a load generator waiting for the right trigger, at any company's scale.

Detail & sources

GitHub's blog postmortem says the outage began when traffic hit a new peak at its Central US facility and an Istio sidecar reached its concurrency limit — a limit a misconfigured monitoring policy tracked on the host service but not on the sidecar itself, so no alert fired before it cascaded. Four HAProxy nodes then exhausted their own flow limits, degrading the gateway auth path and causing widespread authentication failures. Separately, delayed replies from one internal endpoint triggered a latent retry bug in VS Code that amplified traffic roughly 10x and delayed recovery of the Copilot Token Service specifically. At peak, web and API error rates hit about 20% and archive/raw-content downloads about 50%; the incident ran 7 hours 47 minutes, with Actions degraded until roughly 18:03 UTC and Copilot fully recovered by 21:02 UTC. GitHub says it's now applying consistent retry limits and retry budgets across service-to-service calls and reviewing lower-priority CPU/memory alerts that could miss the next cascading failure.

AI Research & Security19 Aug

Google's Mandiant used an AI agent pipeline to find 100+ critical vulnerabilities in stolen source code — in two days

Why it matters: This isn't a lab demo — Mandiant has run the system for about 10 months across real incident-response and red-team work, and it's already produced CVEs in shipped software, which means offense-and-defense AI-assisted code auditing has moved from research promise to operational tool on both sides.

Detail & sources

Mandiant's Agentic Vulnerability Discovery Harness (AVDH) combines specialized LLM agents with deterministic orchestration and expert-defined security methodology: an Explorer agent profiles a target codebase and picks what to focus on, specialist agents dig into authentication, authorization, routing and domain-specific attack surfaces, and a synthesis agent builds a threat model before findings go to human validation. Applied to stolen corporate source-code repositories, AVDH surfaced more than 100 critical true-positive vulnerabilities within two days. Over roughly 10 months of internal use across incident response, penetration tests, red-team exercises and proactive code review, the system has run thousands of analysis pipelines, generated tens of thousands of findings, and produced 12 assigned CVEs in widely deployed open-source software and browser extensions, including two in Drupal (CVE-2026-13242, CVE-2026-55803). Mandiant is publishing the methodology and recommends any team adopting similar systems keep human validation in the loop, since a share of findings are discarded after manual review.
