Cross-Lab × API Security11–12 Aug

A single shared encryption key exposed hidden AI reasoning across OpenAI, Anthropic, and Google

Why it matters: any team piping reasoning-model output through agent logs, evals, or public repos should assume those traces are decodable — the flaw doubles as a credential leak, an IP-theft vector for distilling rivals' models, and a blind spot for prompt-injection payloads hidden inside "encrypted" reasoning that security tooling never inspects.

Detail & sources

Researchers at the ELLIS Institute Tübingen and Max Planck Institute found that OpenAI, Anthropic, and Google all encrypt reasoning tokens returned between API calls with one shared global key per provider, rather than binding them to a session or account. That let the team replay reasoning blocks captured from a stronger model into a weaker, jailbroken sibling from the same provider and read the original chain of thought back out in plaintext — including from models like Claude Opus. Decoding 315,320 reasoning blocks scraped from 6,708 public agent-trajectory logs on GitHub and Hugging Face recovered 182 real credentials: 62 live API keys, 33 passwords, and 30 personal email addresses. Beyond credential theft, the researchers flagged three more attack paths: distilling a rival's proprietary reasoning patterns to train competing models, extracting private data from shared logs, and hiding prompt-injection payloads inside encrypted blocks that monitoring tools can't see. All three vendors deployed server-side mitigations after disclosure, closing the live replay path on current API builds — but reasoning blocks already posted publicly in historical logs remain decodable.

Supply Chain × LiteLLMreported 12 Aug

CloudSEK maps March's LiteLLM supply-chain breach to 2,500+ organizations and 434,000 CI/CD pipelines

Why it matters: a compromise that lived on PyPI for just 40 minutes back in March is still growing in scope five months later, and the stolen data specifically includes AI service keys alongside standard cloud credentials — a reminder that brief supply-chain windows can have long, expanding blast radii, and that AI infrastructure tooling is now a deliberate target, not incidental collateral.

Detail & sources

Threat group TeamPCP compromised the CI pipeline of Aqua Security's Trivy scanner, which LiteLLM's own build process automatically pulled in, letting attackers push two poisoned LiteLLM releases (1.82.7 and 1.82.8) to PyPI for roughly 40 minutes in March. A malicious Python startup file ran on every Python process launch — not just when an application imported LiteLLM — harvesting cloud keys, repository tokens, and AI service credentials from developer workstations and CI/CD build runners. CloudSEK's newly published dataset, built from roughly 434,000 files the attackers captured, now carries high-confidence matches to corporate infrastructure at Nvidia, Samsung Electronics, Cisco Systems, Siemens, S&P Global, ServiceNow, Deloitte, Vodafone, X Corp, Zscaler, FedEx, Volkswagen, Thales, and London Stock Exchange Group, among more than 2,500 organizations and 434,000 exposed CI/CD pipelines in total.

Security × VMwareescalating through 12 Aug

A critical VMware vCenter flaw is now under active exploitation across 47 countries

Why it matters: vCenter sits underneath a huge share of enterprise virtualization — including the infrastructure many teams run AI and other workloads on — and with no vendor workaround available, patching is the only defense while a global exploitation campaign is already underway.

Detail & sources

CVE-2026-59310, a directory-traversal flaw in VMware vCenter Server carrying a 9.8 CVSS score, was disclosed in Broadcom advisory VMSA-2026-0006 on July 29; an exploitation campaign began around August 3 and has since been observed hitting 361 victim IP addresses across 47 countries. Attackers chain the path-traversal bug to achieve code execution, then deploy a malicious cron job for persistence using reverse_ssh, an open-source tool that opens an SSH tunnel back to attacker-controlled infrastructure. Broadcom has not published a workaround; the only remediation is patching to vCenter 9.1.0.0300, 9.0.2.0100, or 8.0 U3k / 8.0 U2f.

Security × Zoompatched 11 Aug

Zoom patches a zero-click "Zoomsday" flaw letting meeting participants silently hijack other attendees' devices

Why it matters: the bug required no clicks and no visible warning to the victim — just being in the same meeting — across every OS Zoom supports, which makes this an urgent patch-now item rather than a routine advisory, even with no known active exploitation yet.

Detail & sources

Dubbed "Zoomsday" and tracked as CVE-2026-53413, the flaw lives in Zoom's screen-share annotation feature, which relies on a proprietary protocol opening a direct communication channel between the person sharing their screen and viewers. A malicious participant could compromise a targeted attendee's device simply by joining or hosting a meeting, with no warning or visible indication to the victim. The bug affects every OS Zoom supports — Windows, macOS, Linux, iOS, and Android. Zoom shipped fixes on August 11 across four bulletins (ZSB-26015 through ZSB-26018); users should update to Zoom Workplace 7.1.5 or 7.0.6, Zoom Rooms 7.1.5, and Meeting SDK 7.1.5. Zoom has not reported active exploitation or a public proof-of-concept so far.
